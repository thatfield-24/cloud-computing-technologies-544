# Lab 06: Review Questions

| Topic | What this lab did | The question to answer | Answer |
| :--- | :--- | :--- | :--- |
| **Secret storage** | Gemini key and database password in SSM SecureString | Where else could each leak from (shell history, process lists, logs, screenshots, Git)? | These could be leaked from hardcoded Git commits, terminal shell histories (`~/.bash_history`), process listings (`ps aux`), or unencrypted environment dumps. |
| **Least privilege** | Each role reads one parameter | What would change if both roles had `ssm:*` on `*`? | Any compromise of a single service would allow an attacker to read, alter, or delete all parameters across the AWS account, including master database passwords. |
| **Network exposure** | App instances accept port 3000 only from the ALB, and the database accepts 5432 only from the app security group | Why is the ALB open to the internet but the instances and the database are not? | The load balancer acts as the public entry point handling TLS and routing. This keeps backend  instances and DBs in private subnets reducing exposure to direct SSH, database exploits, or unauthenticated attacks. |
| **Shared security group** | Both tiers share one app security group, which the database rule allows | What can an advisor instance do that it should not be able to do? How would you fix it? | The advisor instance can directly query/connect to PostgreSQL. Fix: Create separate security groups (`weather-app-sg` and `advisor-sg`), allowing DB access only from `weather-app-sg`. |
| **Database login** | The app logs in as the master user | What would you create instead, and which privileges would it need (think: only lookups, only SELECT and INSERT)? | Create a non-root application user (`app_user`) granted explicit permissions only on necessary tables: `GRANT SELECT, INSERT ON lookups TO app_user;`. |
| **Encryption** | Storage is encrypted at rest, and the connection uses TLS with certificate verification | What does the certificate check protect against that TLS without it does not? | The certificate verifies the server's identity against the trusted CA, protecting against Man-in-the-Middle (MitM) attacks, spoofed endpoints, and DNS poisoning. |
| **SQL injection** | All queries use placeholders | Show one line of the app and say what would go wrong if it built SQL by joining strings | Line: `cursor.execute(f"SELECT * FROM lookups WHERE zip = '{zipcode}'")`. A malicious input like `98101'; DROP TABLE lookups; --` would execute arbitrary SQL statements. |
| **Backups** | Retention 0, no snapshots | What would you lose if this database held real data, and what would you configure instead? | You would suffer permanent data loss during failures/deletions. Enable RDS automated daily snapshots, multi-AZ deployment, point-in-time recovery (PITR), and non-zero retention (7–30 days). |
| **Data lifecycle** | The database is deleted with no snapshot | Who decides when stored data may be destroyed in a real organization? | Data Governance Officers, Legal/Compliance teams, CISO, and designated Data Owners according to regulatory requirements (GDPR, HIPAA) and corporate retention policy. |
| **Untrusted output** | AI text is HTML-escaped on the page | What could an attacker gain if the page printed raw model output? | Attackers could use a Cross-Site Scripting (XSS) vulnerability via prompt injection, allowing attackers to execute malicious JavaScript in user browsers to steal cookies/tokens or hijack sessions. |
| **Data sent to a third party** | Only zip code and public forecast text | What would you have to change before using a paid or school-owned Gemini account for real users? | Opt out of model training on user inputs, sanitize or restrict PII, tighten API key permissions, and implement rate limiting. |
| **Abuse and cost** | The advisor page is public and the free tier has a quota | How could someone use up your quota, and what could you add (rate limiting, a WAF, authentication)? | An attacker could script automated requests to exhaust API quotas or generate high billings. Add AWS WAF (rate-based rules), API Gateway throttling, and and captcha or a cloudflare turnstile challenge to prevent bots. |
| **Availability** | Fallback answer when Gemini fails, and the app keeps working when the database fails | Why is it important that the response says source: fallback or cache: unavailable? | It provides transparency, letting end users and developers know the data is degraded/stale rather than active, aiding troubleshooting without hiding possible outages. |
